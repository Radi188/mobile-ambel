# Deploying BongPOS Owner to iOS

Target: **external TestFlight** first, App Store release after.

## One-time setup

1. **Apple Developer Program** membership ($99/yr) on the account that owns
   `cross.ambelcoffee.app`.
2. **Create the app record** in [App Store Connect](https://appstoreconnect.apple.com)
   → My Apps → **+** → New App:
   - Platform: iOS
   - Name: `BongPOS Owner`
   - Bundle ID: `cross.ambelcoffee.app` (register it at
     developer.apple.com → Identifiers first if it isn't listed)
   - SKU: anything unique, e.g. `bongpos`
`eas submit` finds the app by bundle ID after you sign in, so no app ID needs to
go in `eas.json`. If you ever want to pin it explicitly — useful when one Apple
account has several apps — add the **Apple ID** number from the app's App
Information page (digits only, e.g. `6749214402`):

```json
"submit": { "production": { "ios": { "ascAppId": "6749214402" } } }
```

The value must be digits only; a placeholder string fails validation before
submit even starts.

## Build + upload

```bash
npm run typecheck          # must be clean
npm run doctor             # must be 18/18
npm run build:ios          # ~15-25 min on EAS
npm run submit:ios         # uploads the finished build to App Store Connect
```

Or do both in one step:

```bash
npm run release:ios        # build --auto-submit
```

The first build prompts for Apple credentials and offers to generate the
distribution certificate and provisioning profile — say yes; EAS stores and
reuses them.

Version numbers are managed remotely (`appVersionSource: "remote"` +
`autoIncrement`), so the build number increments on EAS. Bump the user-facing
`version` in `app.json` by hand for each release (`1.0.0` → `1.0.1`).

## Ad hoc builds (install straight on registered devices)

For testing without TestFlight review: an `.ipa` that installs from a link on
the iPhones registered to the Apple team (`CUQ32KADC2`).

```bash
npm run devices:add        # once per new iPhone — opens a link/QR to register it
npm run build:adhoc        # eas build --platform ios --profile adhoc
```

When the build finishes, open its page on expo.dev on the iPhone (or scan the
QR code) and tap **Install**.

- Only devices in the **ad hoc provisioning profile** can install it. After
  registering a new device, run `npm run build:adhoc` interactively once and
  let EAS add the device to the profile when it asks — then rebuild.
- iOS 16+: the first launch needs **Settings → Privacy & Security → Developer
  Mode** turned on.
- Ad hoc builds talk to the same servers as production (BongPOS / Ambel, picked
  on the login screen) — test orders are real orders.

## Turning on external TestFlight

Internal testing (your own team, up to 100 people) works as soon as the build
finishes processing — no review. **External** testing needs one extra pass:

1. App Store Connect → your app → **TestFlight**.
2. Wait for the build to leave "Processing" (10–30 min).
3. Fill in **Test Information** (required before external testing):
   - Beta App Description — what testers should try
   - Feedback email, marketing/privacy URLs
   - Demo account: a working username + password, since the whole app is behind
     a login. **Reviewers reject builds they can't sign into.**
4. Create an **External Group**, add the build, invite testers by email or
   public link.
5. Submit for **Beta App Review** — usually under 24h. Approval carries over to
   later builds unless you change something significant.

## Before the App Store submission

- **App Privacy** questionnaire: the app collects photos (product images) and
  account credentials — declare them.
- Screenshots for 6.7" and 6.5" iPhones.
- Description, keywords, support URL, privacy policy URL (required).

## Notes / gotchas

- `assets/logo.png` must stay a **real PNG with no alpha channel**. It was a
  JPEG named `.png`, which fails App Store validation — converted to a true
  1024×1024 PNG. If you replace the logo, run:
  `sips -s format png -Z 1024 new-logo.jpg --out assets/logo.png`
- The app talks to two backends, picked on the login screen (`BACKENDS` in
  `lib/serverConfig.ts`): BongPOS at `https://api.bongpos.com`
  (`EXPO_PUBLIC_API_BASE_URL`) and Ambel at
  `https://ambel.crosscambodia.com/api` (`EXPO_PUBLIC_AMBEL_API_URL`). Either
  address can be overridden per device from the "Server" link on the login
  screen; without an override, TestFlight builds hit **production data** —
  every test order is a real order.
- Product images 404 until `uploads/` is deployed to the API server (see the
  notes on the backend `.gitignore`).
- `ios/` and `android/` are gitignored and regenerated by EAS on each build, so
  all native config must live in `app.json`, never in those folders.
